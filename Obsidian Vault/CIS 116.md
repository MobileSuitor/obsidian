<u>Chapter 1</u>
*Objectives*
	- describe virtualization
	- understand the three properties outlined by Popek and Goldberg
	- understand the two key trends that drive virtualization
	- understand why virtualization is a key tech in datacenters

- Virtualization - the process where physical servers are converted into VMs. Makes more efficient use of hardware resources to run several individual computers from one physical platform
- Popek and Goldberg's three properties
	1. *Fidelity* - virtual environment should be identical to physical
	2. *Isolation*/*Safety* - VMM (**hypervisor**) must have control of system resources
	3. *Performance* - little or no difference in performance
- Type 1 vs Type 2 hypervisors
	- *Type 1* - AKA bare metal hypervisor, acts as its own OS and sits directly on top of hardware resources. Less overhead and better performance, but is more difficult to set up for beginners
	- *Type 2* - software like VirtualBox that request resources from the host OS in order to manage and run VMs
- Moore's Law - processing power doubles roughly every 18 months. Originally applied to transistor density, but now is applied to many technologies
- Trends that accelerate virtualization
	- *Consolidation* - running multiple workloads on a single host
	- *Containment* - deploying new applications in a virtual infrastructure
	- Move from an infrastructure enhancer to a business enabler
- Advantages of Virtualization
	- Hypervisors allow multiple virtual servers to run on a single host; fewer servers used and more efficient resource consumption
	- provides large ROIs by removing cost from infrastructure
	- Desktops and applications can also be virtualized

<u>Chapter 3</u>
*Objectives*
	- what comprises a VM
	- understand how resources appear in a VM
	- understand how requests move through hypervisor and back again
	- Open Virtualization Format

- Virtual Machine composition
	- set of data files
	- instantiation of a container that runs an application
- Virtual hardware - from the VMs perspective, it is a physical server (*Fidelity*). Virtualization approaches each resource differently
	- vCPUs - scheduled slices on a physical CPU. A physical processor core is roughly equivalent to a vCPU. There is little ability to manage vCPUs aside from adjusting the amount
	- Virtual memory - mapped to physical memory but is managed by the hypervisor. VMs can only see and utilize what has been allocated. Usually the resource that runs out first
	- Virtual networking - VM to VM communication is possible without traversing the physical network. This is the area most apt to be misconfigured
	- Virtual storage - storage is presented to VMs in a number of ways. VMs can "see" the C: drive, but it is actually a file on a much larger storage device
- Open Virtualization Format (OVF)
	- vendor neutral industry standard
	- cross vendor and cross platform
	- used to export and import VMs from one platform to another
	- can bundle VMs into one package using .ova extension
